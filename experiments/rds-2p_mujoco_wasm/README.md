# rds-2p_mujoco_wasm

Веб-приложение для мастер-класса с роботом-пандой RDS-2P («Панда»):
слева — блочный конструктор правил (Google Blockly) и голосовой ввод,
справа — MuJoCo-симулятор робота в браузере.

Ребёнок собирает правило «ЕСЛИ услышу фразу ТОГДА сделай движение», говорит
фразу в микрофон, модель **Laya** (ONNX Runtime Web, WebGPU → WASM) выбирает
правило, и Панда выполняет движение в симуляторе.

Подробный план — [PLAN.md](PLAN.md). Статус реализации: M0–M2, M4–M5 готовы;
M3 (ONNX-артефакты Laya) собирается `tools/` — без файлов модели приложение
работает в быстром режиме (keywords).

## Запуск

```bash
npm install                      # три, mujoco-js, blockly, onnxruntime-web, tokenizers
python3 tools/serve.py           # http://localhost:8080/  (COOP/COEP, кэш модели)
```

Открыть в Chrome: `http://localhost:8080/`.

Микрофон требует защищённый контекст: localhost — можно сразу; для класса по IP —
`python3 tools/serve.py --https` (самоподписанный сертификат) или флаг
`--unsafely-treat-insecure-origin-as-secure` у Chrome (PLAN.md 8).

## Быстрый старт в классе

1. Ребёнок собирает правило (Blockly: «Правило → если услышу … → тогда …»).
2. Нажимает «Микрофон» и говорит фразу (или печатает в «Проверить фразу»).
3. Панда исполняет цепочку в симуляторе; справа видно, что она «поняла» и с каким процентом.

Готовый набор из 14 правил лежит в `assets/rules/panda_rules.json` и загружается
при первом запуске. «🐾 Мои позы» — панель поверх симулятора: 12 ползунков
(4 лапы × 3 сустава) двигают панду вживую; позу можно сохранить и вставить
в блок «🐾 поза». Правила и позы живут в localStorage.

## Laya в браузере (опционально)

```bash
bash tools/download_models.sh    # tokenizer.json/temperature.json из HF
python tools/export_onnx.py --fp16   # свой ONNX-граф на x86 (см. PLAN.md 7)
```

После появления файлов в `models/laya/` приложение само подхватит модель
(прогресс — в шапке, EP: WebGPU или WASM). До готовности и при неудаче —
мгновенный keyword-режим. Резервный серверный режим: `--nlu-url` у `serve.py`
(браузер ходит только в бэкенд, ключей во фронтенде нет).

## Структура

```
index.html            каркас: Blockly слева, симулятор справа
src/
  main.js             сборка приложения и поток «фраза → правило → движение»
  blocks/             кастомные блоки Blockly + сериализация блоков ↔ правил
  rules/              модель/хранилище правил, компиляторы в вопрос Laya и в движения
  nlu/                keywords-fallback, laya_encode (порт ONNX-входов), worker ORT, api-прокси
  speech/             Web Speech API (ru-RU)
  sim/                MuJoCo-симулятор, менеджер поз (norm→ctrl), плеер движений
  robot/motions.js    программы движений (перенос из robot_routine_handler.py)
tools/                serve.py, export_onnx.py, download_models.sh, yaml_to_json.py, verify…
assets/               сцена+меши (копия wasm_demo), poses.json, пресет правил
```

## Docker (веб-образ для любых машин)

Самодостаточный образ: раздаёт приложение, меши, ONNX-политику, модель Laya и
офлайн-голос Vosk (всё качается на этапе сборки, ROS не нужен):

```bash
docker/build_web.sh          # → rds2p/web:latest (WITH_MODELS=0 — лёгкий, без Laya/Vosk)
docker/run_web.sh            # http://localhost:8080  (PORT=… — другой порт)
```

Для доступа с других устройств по сети микрофону нужен https — запускайте
`serve.py --https` (или reverse-proxy с TLS).

## Проверка «своих же примеров»

```bash
python3 tools/check_examples.py       # каждая фраза-пример должна выбирать свой вариант (пресет + шаблоны)
node tools/check_motor_angles.mjs     # цепочка моторы→суставы: «цифровой нуль» = [0×12], позы конечны
```

## Известные упрощения / честные заметки

- Маппинг поз: полный порт цепочки ROS2 — `pose → units (min+(max−min)·p) →
  радианы мотора (zero_offset, reversed) → углы суставов (reversed_axis,
  axis_rotate 45°/90°, параллелограмм голени)`; формулы из ftservo_ros
  `motor_controller` + rds_2p `motor_to_joint_bridge` (см. src/sim/motorAngles.js).
  Данные калибровки — из `calibrate.json` робота и `joint_offsets.yaml`; на
  другой сборке меняется только таблица MOTORS.
- Именованные позы идут ТОЧНЫМИ углами из `assets/pose_angles.json` (таблица
  второго агента: реплика цепочки percent→units→joint). Конвенции ROS-моста и MJCF
  совпадают (сверено с тренировочными keyframes `pre_recovery`/`lying_down` —
  знаки 1-в-1), конверсия тождественная (`main.js toSimAngles`). Норм-цепочка
  остаётся для слайдеров и пользовательских поз.
- `tools/check_motor_angles.mjs` — проверка цепочки («цифровой нуль» → [0×12])
  и таблицы поз; `tools/check_examples.py` — прогон своих же примеров фраз через
  Laya-ONNX (24/26, единственный промах «спи»→Лежать — ограничение модели).
- Классификатор Laya: вариантам в промпт идут НАЗВАНИЯ (не внутренние id!) —
  с id-префиксами модель сыпется («дай лапу» 99% → мусор). Абстрактные
  гейт-вопросы («команда или разговор») в русском нестабильны — вставляйте
  конкретные варианты с примерами фраз.
- Сцена «зоопарк»: травяная лужайка, деревья, пруд, цветы; тени 2048px,
  зеркальный Reflector убран (мешал читаемости и жрал GPU).
- Микрофон — Web Speech API (Chrome/Edge). Чек-лист, если не работает:
  1) адрес должен быть защищённым: `localhost` — ок, по IP — `serve.py --https`;
  2) разреши микрофон: значок в адресной строке → «Микрофон» → разрешить;
  3) распознавание в Chrome идёт через онлайн-сервис Google — без доступа к нему
     будет ошибка «нет связи» (кнопка скажет об этом тостом);
  4) Firefox и встроенные браузеры редакторов Web Speech не поддерживают —
     поле «напиши фразу» рядом работает всегда.
- Кувырок (`rotate`) — скриптованный переворот базы (в этом wasm-билде силы до
  физики не доходят, поэтому и драг кинематический). Трот (`run`) — best-effort.
- Немоторные команды (`help`, `silence` и т.п.) — эффект в интерфейсе, как на роботе.
- Модель Laya используется целиком, срез словаря не делается.
