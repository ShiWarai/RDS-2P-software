# Three.js: неверная глубина при чтении общего renderer

## Симптом
При отдельном проходе глубины фон может выглядеть как близкая поверхность; после прохода может меняться область основного рендера.

## Причина
Цвет scene.background — обычный RGB, а не упакованная глубина. Perspective depth нелинейна. Глобальные определения viewport/scissor renderer могут отличаться от настроек активного render target.

## Решение
- На проходе отключать background, очищать RGBA белым sentinel и явно обрабатывать «нет поверхности».
- Использовать MeshDepthMaterial/RGBADepthPacking и распаковку из закреплённой версии Three.js; затем переводить перспективную глубину в осевые метры.
- У render target собственные viewport/scissor. Не менять глобальные определения без необходимости; восстанавливать прежний target и сцену в finally.
- Измерять частоту по активному времени. После возврата из скрытой вкладки начинать измерительное окно заново.

## Проверка
`node --test tools/check_depth_math.mjs`; `/tools/check_depth_map.html`; `python tools/check_depth_browser.py --perf` при запущенном локальном сервере.
Контроль: известные плоскости, пустой фон, окклюзия, active-target GL-state, исключение readback, закрытие и восстановление контекста.

## Границы
Проверено для Three.js 0.181.2, стандартной перспективной камеры и непрозрачной геометрии. Для logarithmic/reversed depth, alpha-test и настоящих сенсоров требуется отдельная проверка. Подробный протокол — `.kiro/specs/depth-map/evidence.md`.
