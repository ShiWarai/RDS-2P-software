# rds-2p_mujoco_wasm — план разработки

Мастер-класс для школьников (10–14 лет): интерактивная веб-страница, где ребёнок собирает правила из блоков, говорит фразу в микрофон, и робот-собака «Панда» (RDS-2P) выполняет движение в MuJoCo-симуляторе прямо в браузере.

Статус: реализовано в коде (M0–M5; M3 включается при наличии
артефактов `models/laya/`), см. README.md и историю каталога.

---

## 1. Что делаем

Одна страница, две половины экрана:

- **Слева — конструктор правил.** Блочный редактор (Google Blockly) на русском языке:
  правило = «ЕСЛИ услышу фразу ТОГДА сделай цепочку действий». Действия: готовая команда
  (`дай лапу`, `лежать`, `равняйся`, `служить`, `беги`…), своя поза (редактор 12 ползунков)
  или пауза. Плюс кнопка микрофона и поле «проверить фразу».
- **Справа — симулятор.** MuJoCo WebAssembly + three.js (рюкзак `wasm_demo`), модель
  `rds-2p_feetonly` с 12 позиционными актуаторами. Здесь же панель ручных команд,
  ползунки приводов и управление камерой.

Поток работы ребёнка:

```
собрал правило(а) → нажал микрофон → распознан текст (Web Speech, ru-RU)
→ Laya классифицирует текст по правилам → Панда исполняет цепочку движений
```

UI-референс — страница `/laya` сервиса `system-one-rknn` (тёмная техно-тема, таблица
ответов и процентов), но интерфейс переработан под детей и правила.

## 2. Решения, принятые в обсуждении

| Вопрос | Решение |
|---|---|
| Блок-редактор | **Google Blockly**, свои блоки на русском |
| Содержание правил | **Цепочки действий + редактор своих поз** (12 слайдеров, сохранение позы) |
| Где считать Laya | **В браузере: ONNX Runtime Web, WebGPU → WASM.** Загрузка стартует после открытия UI и симулятора; индикатор — кружок/прогресс в углу. До готовности модели работает «быстрый режим» по ключевым словам |
| Голос | **Web Speech API (ru-RU)**, интернет в классе есть; текстовое поле — всегда доступный запасной вход |
| Аудитория | **10–14 лет** |
| Папка проекта | `experiments/rds-2p_mujoco_wasm` (рядом с `wasm_demo`) |
| Размер Laya | **Срез словаря не делаем — модель используется как есть.** Если в классе окажется тяжело, переключаемся на серверный режим, а не режем граф |
| Резервный сервис | На бэкенде (`serve.py`) можно указать внешний сервис модели (OSM — system-one-npu или облачный с ключом). **Браузер обращается только к нашему бэкенду; ключи хранятся на сервере и в статику не попадают** |

## 3. Наследие `wasm_demo`

Берём:

- `src/mujocoUtils.js` — загрузка сцены в FS Emscripten, построение three.js-сцены,
  `loadSceneFromURL`, `getPosition/getQuaternion`, `drawTendonsAndFlex`;
- связку `three` + `mujoco-js` (версии из `experiments/wasm_demo/package.json`);
- сцену и меши `assets/scenes/` (копируются в новый проект);
- схему import map + статическая раздача `node_modules` (сборщик на этапе класса не нужен).

Меняем:

- `main.js` пишется заново: рендер в контейнер (правая половина), а не на всё окно;
- убираем `lil-gui`, вместо него — детские панели;
- добавляем прослойки: правила, NLU (Laya), речь, программы движений;
- добавляем менеджер поз: `norm → ctrl` (см. 4.5).

### 4.1. Модель правил

```json
{
  "id": "r_1",
  "name": "Дай лапу",
  "examples": ["дай лапу", "поздоровайся", "дай пять"],
  "action": {
    "type": "chain",
    "steps": [
      { "kind": "command", "command": "give_paw" },
      { "kind": "pose",    "pose": "my_pose_1", "hold_ms": 800 },
      { "kind": "wait",    "ms": 500 }
    ]
  }
}
```

- Стартовый пресет — «Команды Панды»: 14 правил из шаблона (JSON в вопросе), которые
  можно редактировать. Немоторные команды (`help`, `silence`, `bind/unbind`,
  `report_command`) исполняются как UI-эффекты (иконка/подсказка), это честно отражаем в UI.
  `unknown` не блок — вместо него порог уверенности.
- Правила и свои позы хранятся в localStorage; кнопки «Скачать/Загрузить JSON», чтобы
  ребёнок унёс свои правила домой.

### 4.2. Компиляция правил в вопрос Laya

Все правила собираются в один `choice`-вопрос:

```json
{
  "model": "laya-multilingual",
  "state": "дай лапу",
  "questions": {
    "command": {
      "type": "choice",
      "instructions": "Выбери команду робота, которой соответствует текст.",
      "criteria": {
        "r_1": "Дай лапу: дай лапу, поздоровайся, дай пять",
        "r_2": "Лежать: лежать, ложись, ляг"
      }
    }
  }
}
```

Ответ (`choice`, `confidence`, `probabilities`) показывается детской картинкой
(«Панда думает: Дай лапу — 87%»), ниже порога — «Панда не поняла, скажи иначе».

### 4.3. Laya в браузере

- **Encode.** Порт `app/laya_encode.py` из `ShiWarai/system-one-rknn`:
  `MAX_LEN=512`, `HEAD_MAX_LEN=256`, `KMAX=64`, спецтокены `CLS=2, SEP=1, PAD=0, MASK=4`,
  опции ≤48 токенов, порядок блоков: head (тип вопроса + instructions) → опции с маркерами →
  state (текст ребёнка) → SEP. Токенизатор — `tokenizer.json` (mmBERT, 256k) через
  `@huggingface/tokenizers` (WASM).
- **Граф ONNX.** 5 входов: `input_ids[1,512]`, `attention_mask[1,512]`, `marker_pos[1,64]`,
  `marker_mask[1,64]`, `qtype[1]` → `logits[1,64]`. Softmax и выбор метки — в JS.
  Граф берём **как есть, полный словарь 256k**; минимальная хирургия — только cast
  `int64 → int32` на входах, если WebGPU EP его потребует.
- **Загрузка.** Модель качается fetch’ем с прогрессом **после** старта UI и симулятора,
  кэшируется (Cache Storage / HTTP-кэш), сессия ORT создаётся в Web Worker, чтобы не
  подвешивать интерфейс. Индикатор в углу: «Учу Панду понимать слова… 37%», затем статус EP.
- **Execution Providers.** Сначала `webgpu`, при неудаче — `wasm` (SIMD; threads при
  cross-origin isolation, заголовки ставит наш сервер). Статус EP виден в UI.
- **Ожидаемая скорость:** WebGPU ~0,3–1,5 с на фразу, WASM int8 ~1–4 с. Для класса приемлемо.
- **Fallback.** До готовности модели (и если она не загрузилась) — `nlu/keywords.js`:
  нормализация текста + совпадение с примерами фраз. Запасной уровень для класса —
  `nlu/api.js` через бэкенд-прокси `serve.py`: внешний сервис модели (system-one-npu
  `/v1/systemone` или облачный сервис с ключом). Адрес и ключ задаются только в конфиге
  сервера; браузер ходит исключительно в наш бэкенд.

### 4.4. Симулятор

- Сцена `rds2p_feetonly_scene.xml`, модель `rds-2p_feetonly.mjcf`: 12 hinge-джойнтов,
  12 `position`-актуаторов с `ctrlrange` (радианы), freejoint, keyframes
  `home / home_higher / pre_recovery / test`.
- **Порядок актуаторов в MJCF:** fl, fr, bl, br × (leg_block, hip, shin).
  Порядок «motor 1..12» из `panda_poses.yaml` полагаем таким же (leg_1..leg_4 × 3) —
  **подлежит проверке** (раздел 12).
- `norm → ctrl`: как `calculate_position` из `motor_calibration.py`:
  `ctrl`: линейно по таблице направлений из ROS2-цепочки (`reversed`/`reversed_axis`):
fl ↓↓↓, fr ↓↑↑, bl ↑↓↓, br ↑↑↑ (см. poseManager.js DIRECTION), где `lo/hi` — `actuator_ctrlrange` джойнта.
  Зеркальность сторон уже зашита в диапазоны модели (fr/br имеют инвертированные range).
- **Погоня за плавностью:** между позами интерполируем (250–500 мс по каждому приводу);
  жёсткие пики `no_limit`-поз (кувырок) разрешаем только для актуатора с временно снятым
  `ctrllimited` и мягким предохранителем ±20% за диапазоном.
- **Программы движений** (перенос последовательностей из
  `ros_packages/src/rds_2p_commands/rds_2p_commands/action_handlers/robot_routine_handler.py`):
  - `give_paw`: `position_give` → (0.5 с) → `position_2` → (0.5 с) → `position_1`;
  - `stand_at_attention`: `position_2`;
  - `dismiss`: `position_1`;
  - `lie_down`: `position_0`, затем **отключение актуаторов (gain=0)** — «плюх» под гравитацией,
    как реальный `EnableTorque(all, 0)`;
  - `pray` (служить): `position_0` → `position_4_0` → `position_4_1` → … → `position_4_n`;
  - `rotate` (кувырок): `position_3_0…3_5` — **best-effort**, честно помечаем как эксперимент;
  - `run`: своей походки в репозитории нет (у робота это внешний сервис) — реализуем
    процедурный трот (синусоиды по hip/shin), «бежит на месте»; `stop_running` останавливает;
  - прочие команды — UI-эффекты (подсказка/список/иконка).
- Сброс: `mj_resetData` + keyframe `home`.

### 4.5. Редактор своих поз

Модальное окно: 12 слайдеров (0…1, центр 0.5 = нейтраль), живой предпросмотр на модели
(пока симуляция активна), «Сохранить позу» → пользовательская поза с именем → доступна
как блок `поставь позу X` в цепочках. `no_limit` детям не показываем.

## 7. Подготовка Laya-модели (главный технический риск)

Источник: HF `ShiWarai/laya-multilingual-rknn` (скрипты экспорта) + чекпойнт
`convaiinnovations/laya` (подпапка `multilingual`, mmBERT-base, MIT).

1. `tools/export_onnx.py`: окружение `laya==0.3.20`, `transformers`, `torch`, `onnx`
   (opset 18), как в карточке модели; получаем `laya_multilingual_seq512.onnx`.
2. Минимальная хирургия графа: cast входов `int64 → int32` (WebGPU EP не любит int64).
   **Словарь не срезаем** — эмбеддинг-таблица 256k остаётся как есть; tokenizer.json не трогаем.
3. Размеры «как есть»: fp16 ≈ 560 МБ, int8 (динамическая квантизация MatMul) ≈ 280 МБ.
   fp16 — основной артефакт для WebGPU; int8 — способ уложиться по сети без среза словаря
   (WASM EP). Обе цифры замеряем на месте, решение — по факту скорости в классе.
4. Верификация: `verify_onnx_vs_service.py` на наборе фраз (argmax-совпадение, цель ≥ 99%;
   больше — предупреждаем). Отдельно — тестовые векторы encode (JS vs Python).
5. Артефакты кладём в `models/laya/`, в git не коммитим (крупные), есть скрипт выгрузки.
6. Если WebGPU не заводится на Intel-графике моноблоков — работаем на WASM; если и это
   медленно или модель долго качается — запасной режим: бэкенд `nlu/api.js` через `serve.py`
   к внешнему сервису модели (system-one-npu или облачный с ключом на сервере).

## 8. Запуск в классе

- `tools/serve.py`: раздаёт проект (index.html, node_modules, assets, models) с
  cache-заголовками и заголовками COOP/COEP (для threads).
- **Прокси на внешний сервис NLU.** В конфиге сервера (аргументы/`.env`):
  адрес сервиса, при необходимости ключ/заголовок авторизации. `serve.py` проксирует
  `POST /api/nlu` → upstream (system-one-npu `/v1/systemone` или облачный сервис),
  подставляя ключ на сервере. В браузере ключей нет никогда; прямой доступ к внешним
  сервисам из фронтенда запрещён — только через бэкенд.
- **Микрофон = защищённый контекст.** Chrome требует https/localhost для захвата микрофона.
  Варианты (проверяем на моноблоках, выбираем один):
  1) `--https` со самоподписанным сертификатом + одноразовое принятие в браузере;
  2) ярлык Chrome с `--unsafely-treat-insecure-origin-as-secure=http://<ip>:<port>`;
  3) локальный запуск на каждом моноблоке (тяжелее: модель качается на каждой машине).
- Чек-лист перед занятием: `chrome://gpu` (WebGPU… «Hardware accelerated»), скорость
  загрузки модели по классовой сети, работа микрофона, кэш модели после первого запуска,
  аварийный режим keywords.

## 10. Риски и меры

| Риск | Мера |
|---|---|
| Размер/скорость Laya в браузере | модель как есть (fp16 ≈ 560 МБ / int8 ≈ 280 МБ), кэш, прогресс при загрузке, keywords-fallback; при провале — серверный режим через внешний сервис, срез словаря не применяем |
| WebGPU на Intel-графике (int64, opset, драйверы) | cast int64→int32 на входах, EP-фолбэк WASM, статус EP в UI, тест на моноблоках заранее |
| Микрофон на http-странице | https/self-signed или флаг Chrome; текстовое поле всегда |
| Физика кувырка/бега в MuJoCo | честные best-effort пометки, безопасные fallback-анимации, не обещаем точность реального робота |
| Порядок моторов 1..12 ≠ порядок актуаторов MJCF | сверить по `calibrate.json` робота или визуально (give_paw поднимает лапу, а не ногу позади) |
| Blockly: свои блоки на русском | заложено в M2; toolbox минимальный, без генерации кода — только JSON правил |
| CORS и ключи внешних сервисов | только бэкенд-прокси в `serve.py`; фронтенд никогда не обращается к внешним сервисам напрямую и не содержит ключей |
| Большая модель в git | `models/` в `.gitignore`, выгрузка скриптом |

## 11. Проверки

- **Encode:** тестовые векторы «текст → input_ids/marker_pos» из Python-реализации, прогон JS-порта.
- **Модель:** `verify_onnx_vs_service.py` — совпадение выбранной метки с ответами RKNN-сервиса.
- **Позы:** таблица `norm → ctrl` для каждой позы из `panda_poses.yaml`; визуальная сверка
  характерных поз (`position_give` — поднятая передняя лапа, `position_2` — стойка) со фото/видео робота.
- **URL-ные сценарии:** «дай лапу», «кувырок не выйдет — не падать», «правило ребёнка ловит свою фразу».
- **Перед классом:** прогон чек-листа из раздела 8 на моноблоке.
