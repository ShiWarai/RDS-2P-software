# FTServo ROS Package

ROS2 пакет для управления двигателями Feetech SCS. Пакет предоставляет высокоуровневый интерфейс для управления сервоприводами через ROS2 топики.

## 🚀 Новые возможности

### 📝 Изменения в версии 0.1.0
- **Удален параметр `transmission_rate`** - упрощена архитектура узла
- **Добавлен параметр `interface_baudrate`** - возможность настройки скорости последовательного порта
- **Оптимизирован код** - убрана неиспользуемая функциональность передачи команд

### ✨ Улучшенная симуляция
- **Реалистичная динамика электрических параметров**: напряжение и ток изменяются в зависимости от нагрузки
- **Плавные переходы**: при включении/выключении моторов и изменении нагрузки
- **Симуляция просадки напряжения**: при увеличении ускорения
- **Настраиваемый PID регулятор**: возможность настройки коэффициентов Kp, Ki, Kd для каждого типа мотора
- **Гибкая настройка поведения**: от агрессивного до консервативного управления через конфигурацию

### 🖥️ Улучшенный GUI интерфейс
- **Фокус на выбранном моторе**: подробная информация только о выбранном моторе
- **Структурированное отображение**: основные, электрические и управляющие параметры
- **Увеличенное окно**: больше места для отображения информации
- **Управление обновлениями**: кнопки очистки, обновления и автоматического обновления
- **Цветные индикаторы статуса**: онлайн/оффлайн/ошибка

### 🔧 Улучшенное управление
- **Массовые операции**: включение/выключение всех моторов одной кнопкой
- **Принудительное обновление**: возможность обновить данные по требованию
- **Автоматическое обновление**: настраиваемая частота обновления информации
- **Настраиваемая скорость порта**: параметр `interface_baudrate` для гибкой настройки связи

## Конфигурация

### Настройка конфигурации

1. Скопируйте пример конфигурации в удобное для вас место:
   ```bash
   cp config/config_example.yaml ~/my_robot_config.yaml
   ```

2. Отредактируйте конфигурацию под ваши двигатели:

```yaml
motor_types:
  SCS40:
    # PID коэффициенты для симуляции
    pid_kp: 20.0            # Пропорциональный коэффициент
    pid_ki: 0.0             # Интегральный коэффициент  
    pid_kd: 0.0             # Дифференциальный коэффициент
    
    # Максимальные значения для симуляции
    max_velocity: 8.7       # рад/с
    max_acceleration: 20.0  # рад/с²

motors:
  leg_block_fl_motor:
    type: "SCS40"
    id: 1
    joint_name: "leg_block_fl_joint"
    zero_offset_units: 512
    min_position_units: 157
    max_position_units: 692
    reversed: false
    
  # Добавьте остальные моторы...
```

Подробная документация по конфигурации находится в `config/README.md`.

## Запуск

### Через launch файл

**Основные параметры:**
- `config_file` - обязательный параметр, путь к YAML конфигурации
- `interface` - последовательный порт (по умолчанию: `/dev/ttyS0`)
- `interface_baudrate` - скорость порта (по умолчанию: `115200`)
- `update_rate` - частота обновления состояний (по умолчанию: `100` Гц)
- `data_rate` - частота обновления телеметрии (по умолчанию: `10` Гц)
- `is_sim` - режим симуляции (по умолчанию: `false`)

> **⚠️ Ограничение Repka Pi 4 (Allwinner H6): штатный UART не поддерживает 1 000 000 baud.**
> Для работы моторов Feetech SCS (SCS40) и их телеметрии нужна скорость шины **1 Мбит/с**. UART-блоки H6 тактируются от 24 МГц с 16-кратной передискретизацией: 1M требует делителя 1.5, а он целочисленный — ядро выставляет делитель 2, и на линии получается реальные **750 000 baud** (проверяется чтением DLL из MMIO 0x05000c00). Поэтому на встроенных портах Repka Pi 4 (`/dev/ttyS0`, uart3 = `/dev/ttyS2`) моторы не отвечают даже при верной обвязке: локальная петля TX-RX при этом работает идеально, т.к. оба канала ошибаются синхронно. На OrangePi 5 той же конфигурации связь есть — DesignWare UART умеет 8×-оверсэмплинг и даёт честный 1M.
> Варианты работы на Repka Pi 4: внешний USB-UART с поддержкой 1M (`interface:=/dev/ttyUSB0`, у FTDI/CH340 1M точный) либо перевод шины на **500 000 baud** (24M/16/3 — воспроизводится точно; регистр скорости моторов 0x06 = 1, применяется после ребута питания шины; в ноде `interface_baudrate:=500000`).

```bash
# Запуск с пользовательскими параметрами (config_file обязателен)
ros2 launch ftservo_ros motor_controller.launch.py \
  config_file:=~/my_robot_config.yaml \
  update_rate:=100 \
  data_rate:=10 \
  interface:=/dev/ttyUSB0 \
  interface_baudrate:=115200 \
  is_sim:=false
```

```bash
# Ещё один вариант запуска
ros2 run ftservo_ros motor_controller_node --ros-args -p config_file:=src/ftservo_ros/config/config_example.yaml -p is_sim:=true

# Запуск с настройкой скорости порта
ros2 run ftservo_ros motor_controller_node --ros-args \
  -p config_file:=src/ftservo_ros/config/config_example.yaml \
  -p interface:=/dev/ttyUSB0 \
  -p interface_baudrate:=1000000 \
  -p is_sim:=false
```

## Топики

### Публикуемые топики

#### Телеметрические данные (высокая частота):
- `/motors/telemetries` (ftservo_ros/msg/MotorTelemetries) - Объединенные данные всех моторов (позиция, скорость, ускорение, включение, температура, ток, напряжение, ошибки)

#### Статическая информация:
- `/motors/joint_mapping` (ftservo_ros/msg/MotorJointMapping) - Привязки моторов к joints (публикуется один раз при запуске)

**Примечание:** В режиме симуляции электрические параметры (напряжение, ток) динамически изменяются в зависимости от ускорения мотора, обеспечивая реалистичную симуляцию поведения реальных моторов.

### Подписываемые топики

- `/motors/commands` (ftservo_ros/msg/MotorCommands) - Синхронизированные команды управления движением всем моторам
- `/motors/params` (ftservo_ros/msg/MotorParams) - Параметры управления моторов (включение/выключение, целевые значения, запись в регистры)

**Примечание:** Сообщения используют только `motor_id` для идентификации моторов. Поле `motor_name` больше не используется для уменьшения размера сообщений. Команды управления обрабатываются сразу при получении, что обеспечивает минимальную задержку управления.

### 📋 Описание сообщений

#### MotorTelemetries
Объединенные телеметрические данные всех моторов:
- `header` - Заголовок сообщения
- `telemetries[]` - Массив телеметрических данных MotorTelemetry

#### MotorTelemetry
Телеметрические данные одного мотора (объединяет критичные и некритичные данные):
- `motor_id` - ID мотора
- `position` - Текущая позиция в радианах
- `velocity` - Текущая скорость в рад/с
- `load` - Текущая нагрузка в %
- `enabled` - Включен ли мотор
- `error` - Есть ли ошибка
- `joint_name` - Имя привязанного joint
- `effort` - Текущее усилие (ток в А)
- `temperature` - Температура мотора в °C
- `voltage` - Напряжение питания в В
- `current` - Ток потребления в А
- `error_code` - Код ошибки
- `error_message` - Сообщение об ошибке

#### MotorParams
Параметры управления для всех моторов:
- `header` - Заголовок сообщения
- `params[]` - Массив параметров MotorParam

#### MotorParam
Параметры управления для одного мотора:
- `motor_id` - ID мотора
- `enabled` - Включение/выключение мотора
- `target_position` - Целевая позиция в радианах
- `target_velocity` - Целевая скорость в рад/с
- `target_acceleration` - Целевое ускорение в рад/с²
- `use_direct_write` - Использовать прямую запись в регистры
- `register_addresses[]` - Адреса регистров для записи
- `register_values[]` - Значения для записи в регистры

#### MotorJointMapping
Статическая информация о привязках моторов к joints, публикуется один раз при запуске узла:
- `header` - Заголовок сообщения
- `bindings[]` - Массив привязок MotorJointBinding

#### MotorJointBinding
Информация о привязке одного мотора к joint:
- `motor_id` - ID мотора
- `joint_name` - Имя joint в URDF
- `motor_name` - Имя мотора в конфигурации
- `motor_type` - Тип мотора (SCS40, etc.)
- `reversed` - Инвертировано ли направление вращения
- `zero_offset` - Смещение нуля в радианах
- `min_position` - Минимальная позиция в радианах
- `max_position` - Максимальная позиция в радианах
- `max_velocity` - Максимальная скорость в рад/с
- `max_acceleration` - Максимальное ускорение в рад/с²

## Параметры

- `config_file` (string) - Путь к файлу конфигурации моторов (обязательный)
- `update_rate` (int) - Частота обновления критичных данных (позиция, скорость, ускорение) (Гц)
- `data_rate` (int) - Частота обновления некритичных данных (температура, ток, напряжение) (Гц)
- `interface` (string) - Интерфейс связи (/dev/ttyS0, /dev/ttyUSB0)
- `interface_baudrate` (int) - Скорость последовательного порта (по умолчанию: 115200)
- `is_sim` (bool) - Режим симуляции

## Режим симуляции

Для тестирования без реальных моторов включите режим симуляции:

**Важно:** В симуляции скорость и ускорение интерпретируются как **ограничения**, а не постоянные значения. Это соответствует поведению реальных Feetech моторов:
- Нулевая скорость = максимальная скорость
- Нулевое ускорение = максимальное ускорение
- Реальное ускорение вычисляется на основе изменения скорости

```bash
ros2 launch ftservo_ros motor_controller.launch.py config_file:=~/my_robot_config.yaml is_sim:=true
```

### 🔋 Динамика электрических параметров

В режиме симуляции реализована реалистичная динамика электрических параметров:

**Напряжение:**
- Нормальное значение: 8.4В
- При увеличении ускорения: падает до 7.4В (симуляция просадки)
- При отключении мотора: плавно возвращается к 8.4В

**Ток:**
- Минимальное значение: 0.1А (режим ожидания)
- При увеличении ускорения: растет до 1.0А
- При отключении мотора: плавно возвращается к 0.1А

**Плавные переходы:**
- При включении/выключении: 0.5 секунды
- При изменении нагрузки: 0.2 секунды
- Интерполяция между значениями для реалистичности

### Особенности симуляции:
- Моторы не подключаются к реальному оборудованию
- Состояние моторов симулируется с учетом динамики
- Команды обрабатываются виртуально
- Интерфейс не используется (даже если указан)
- Моторы по умолчанию отключены (`enabled: false`)
- Полезно для тестирования алгоритмов управления
- Реалистичная симуляция электрических параметров

## Примеры использования

```bash
# Установка позиций, скоростей и ускорений для всех моторов
ros2 topic pub /motors/commands ftservo_ros/msg/MotorCommands "
header:
  stamp:
    sec: 0
    nanosec: 0
  frame_id: 'base_link'
commands:
- motor_id: 1
  target_position: 1.57
  target_velocity: 2.0
  target_acceleration: 10.0
- motor_id: 2
  target_position: -1.57
  target_velocity: 1.5

"
```

```bash
    nanosec: 0
  frame_id: 'base_link'
params:

  enabled: true
  target_position: 0.0
```

## 🚀 Производительность и оптимизация

### Оптимизация архитектуры
- **Упрощенная обработка команд**: команды управления обрабатываются сразу при получении
- **Эффективное использование памяти**: убраны неиспользуемые таймеры и функции
- **Настраиваемые частоты обновления**: `update_rate` для критичных данных, `data_rate` для телеметрии
- **Гибкая настройка связи**: параметр `interface_baudrate` для оптимизации пропускной способности

### Рекомендации по настройке
- **Для высокоскоростного управления**: используйте `update_rate:=200` и `interface_baudrate:=1000000`
- **Для экономии ресурсов**: используйте `update_rate:=50` и `data_rate:=5`
- **Для отладки**: используйте `update_rate:=10` и `data_rate:=1`

## Устранение неполадок

### Ошибка "Failed to initialize SCS controller"

1. Проверьте права доступа к интерфейсу:
   ```bash
   sudo chmod 666 /dev/ttyS0
   ```

2. Убедитесь, что интерфейс существует:
   ```bash
   ls -la /dev/tty*
   ```

3. Проверьте конфигурацию моторов в YAML файле

### Ошибка "Motor config not found"

1. Проверьте правильность имен моторов в конфигурации
2. Убедитесь, что YAML файл корректно отформатирован
3. Проверьте путь к файлу конфигурации
